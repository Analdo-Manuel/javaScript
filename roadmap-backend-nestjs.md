# 🛠️ PROJETOS EM DETALHE

> Para todos: repositório próprio no GitHub, `README.md` com descrição, como correr e exemplos, e commits pequenos e frequentes.

## Projeto 1: Jogo de adivinhar o número + Calculadora (Dias 6-7)
**Objetivo:** praticar lógica, condições, ciclos e funções.

**Requisitos:**
- Jogo: o computador escolhe um número de 1 a 100 e o utilizador tenta adivinhar, com dicas "maior" ou "menor" e contagem de tentativas.
- Calculadora no terminal: soma, subtração, multiplicação, divisão, com validação (ex.: divisão por zero).
- Menu principal para escolher entre os dois programas.

**Ferramentas:** Node.js e o módulo `readline` ([docs](https://nodejs.org/docs/latest/api/readline.html)).

**Extras:** dificuldade (fácil/médio/difícil) e histórico de operações.

## Projeto 2: Gestor de tarefas no terminal + API pública (Dias 13-14)
**Objetivo:** POO, arrays, async/await e tratamento de erros.

**Requisitos:**
- Classe `Tarefa` (id, título, estado, data) e classe `GestorDeTarefas` (adicionar, listar, concluir, remover).
- Guardar tarefas num ficheiro JSON com `fs`.
- Parte 2: consumir uma API pública com `fetch` e mostrar os resultados formatados (ex.: [REST Countries](https://restcountries.com/), [PokéAPI](https://pokeapi.co/) ou [ExchangeRate API](https://www.exchangerate-api.com/)).
- Tratar erros de rede com `try/catch`.

**Extras:** filtrar por estado, pesquisar por título.

## Projeto 3: API de livros/produtos em Node puro (Dias 20-21)
**Objetivo:** entender HTTP e REST antes de usar frameworks.

**Requisitos:**
- Servidor com o módulo `http` (sem Express).
- Rotas: `GET /livros`, `GET /livros/:id`, `POST /livros`, `PUT /livros/:id`, `DELETE /livros/:id`.
- Dados guardados num ficheiro `db.json`.
- Respostas em JSON com status codes corretos (200, 201, 400, 404, 500).
- Testar tudo no Postman/Insomnia e guardar a coleção no repositório.

**Extras:** pesquisa por query string (`?autor=...`), variável `PORT` via `.env`.

## Projeto 4: Converter o Projeto 3 para TypeScript (Dias 27-28)
**Objetivo:** tipagem e organização.

**Requisitos:**
- Configurar `tsconfig.json` e scripts no `package.json`.
- Criar `interface Livro` e tipos para os pedidos e respostas.
- Separar em ficheiros: `routes`, `services`, `types`.
- Sem `any` no código.
- Criar uma classe `LivroService` com métodos tipados.

**Extras:** ativar `strict: true` e corrigir todos os erros.

## Projeto 5: API de Tarefas com NestJS (Dias 34-35)
**Objetivo:** dominar o núcleo do Nest.

**Requisitos:**
- Módulo `tasks` com Controller, Service e DTOs (`CreateTaskDto`, `UpdateTaskDto`).
- Endpoints CRUD completos com dados em memória (array).
- Validação com `class-validator` (título obrigatório, estado válido).
- Erros com `NotFoundException` e `BadRequestException`.
- Filtro por estado e pesquisa por texto.

**Extras:** paginação (`?page=1&limit=10`).

## Projeto 6: Tarefas com PostgreSQL + Prisma (Dias 41-42)
**Objetivo:** persistência real e relações.

**Requisitos:**
- Modelos `User` e `Task` com relação 1:N (um utilizador tem várias tarefas).
- Migrations com Prisma.
- Módulos `users` e `tasks` a usar o `PrismaService`.
- Configuração da base de dados via `@nestjs/config` e `.env` (com `.env.example` no repositório).
- Endpoint para listar as tarefas de um utilizador.

**Extras:** categorias (relação N:N) e *soft delete*.

## Projeto 7: API de Blog com autenticação (Dias 48-49)
**Objetivo:** autenticação, autorização e relações mais complexas.

**Requisitos:**
- Modelos: `User`, `Post`, `Comment` (e opcionalmente `Tag`).
- Registo e login (bcrypt + JWT).
- Guard para rotas protegidas; roles `ADMIN` e `USER`.
- Regras: só o autor edita/apaga o seu post; ADMIN pode apagar qualquer post ou comentário.
- Listar posts com paginação e incluir autor e contagem de comentários.
- Helmet, CORS e rate limiting ativos.

**Extras:** refresh token, upload de imagem de capa.

## 🏆 Projeto Final: API de Gestão de Stock/Loja (Dias 55-56)
**Objetivo:** juntar tudo num projeto de portfólio.

**Requisitos:**
- Entidades: `User`, `Product`, `Category`, `Order`, `OrderItem`, `StockMovement`.
- Autenticação JWT com roles: `ADMIN`, `MANAGER`, `CLIENT`.
- Regras de negócio: não permitir vender sem stock, atualizar stock ao criar/cancelar uma encomenda (usar transação do Prisma), calcular o total.
- Endpoints de relatório (ex.: produtos com stock baixo, vendas por período).
- Validação completa, tratamento global de erros e paginação.
- Testes unitários dos services principais e pelo menos 2 testes e2e.
- Swagger em `/api/docs`.
- Docker Compose (API + PostgreSQL).
- Deploy online e link no README.

**README deve ter:** descrição, tecnologias, diagrama simples das entidades, como correr localmente, link do Swagger e do deploy.
